## 2) vLLM —— 必须钉在 0.11.0,原因是 CUDA 版本红线(2026-07-02 实测踩坑):
##    - 最新 vllm 0.24 / torch 2.11 默认拉 CUDA 13 系依赖(nvidia-*-cu13),
##      而宿主驱动 550.90.07 只到 CUDA 12.4(cu12.x 靠小版本兼容可跑,cu13 需要 580+ 驱动,起不来)。
##    - vllm==0.11.0 默认带 torch 2.8 + nvidia-*-cu12,550 驱动可用,且完整支持 qwen3_vl 架构。
##    - 镜像速度实测:USTC ~14-70MB/s ≫ 清华 ~0.4MB/s(大文件疑似限速),pip 一律 -i USTC。
env -u http_proxy -u https_proxy -u all_proxy pip install -i https://mirrors.ustc.edu.cn/pypi/simple "vllm==0.11.0"
## 更新(2026-07-02 下午,实测版本矩阵后钉死):当前环境 = **vllm==0.19.1**。
## 版本矩阵(PyPI requires_dist 逐版查证,别再猜):
##   vllm 0.12-0.13→torch2.9.0 / 0.14-0.16→2.9.1 / 0.17-0.19→2.10.0 / 0.20+→2.11.0
##   torch 2.8/2.9.x/2.10.0 = nvidia-*-cu12(550 驱动可用);torch 2.11+ = cu13(需 580+ 驱动)
##   Qwen3_5(Moe)ForConditionalGeneration 自 vLLM v0.17.0 进注册表(Qwen3.5/3.6 通用)
## → 0.19.1 = 支持 Qwen3-VL + Qwen3.5/3.6 + cu12 的唯一甜点位;0.20+ 全是 cu13,驱动不升就别装。
## (⚠ 曾误装 0.22.1:它钉 torch 2.11-cu13,torch import 直接挂 ncclDevCommDestroy;已回滚重升。)
env -u http_proxy -u https_proxy -u all_proxy pip install -i https://mirrors.ustc.edu.cn/pypi/simple "vllm==0.19.1"

## 13) ⚠ 本地补丁(2026-07-03,恢复环境后若从零重装需重打;GPFS 备份的 env 里已含)
# lmms-eval 0.7.2(main 同样存在)的 qwen3_vl 模型类 bug:视频总帧数 < max_num_frames 时
# qwen-vl-utils 抛 "nframes should in interval [2,N]",整个 rank 崩掉、其余 rank 卡 barrier。
# 补丁位置(两处都要打!):
#   ① models/chat/qwen3_vl.py —— ⚠这才是 --model qwen3_vl 实际跑的类(0.7.2 默认解析到 chat 变体),
#      在 batched_messages 组装后遍历所有 video 元素,逐个探测实际帧数并钳制 nframes;
#   ② models/simple/qwen3_vl.py —— 备用变体,同样已打(视频元素 append 处)。
# 逻辑:仅当走 nframes 模式且视频过短时,把 nframes 钳到实际总帧数(向下取偶)。其余行为与社区默认完全一致。
# 协议表述:"uniform max_num_frames sampling; clips shorter than N frames use all frames (floor-to-even)"。

## 17) 8 卡实例的 P1 收尾命令(2026-07-04;两组可并行,各占 4 卡,注意端口错开)
